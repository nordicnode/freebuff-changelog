- PR #1573: cli: scan only the seam for a completable think tag
  PR Description: ## Why

Inside a text block, the streaming parser could only ever complete a `think` tag in two places: at the seam (the block's tail is a partial tag and the new delta finishes it) or wholly inside the new delta. The old code found those two cases by concatenating the block with the delta and searching the result — O(block) per chunk on any text that contains `<`, which is ordinary in code (`JSX`, XML, `a < b`). Over a stream that is quadratic.

## What changes

`appendTextWithThinkParsingToBlocks` checks the seam and the delta instead, and concatenates the block only when a tag is actually completable there:

- the seam probe reads at most `MAX_TAG_LENGTH_PLUS_ONE` characters from the block's tail, never the block;
- `text.includes('<think')` / `text.includes('</think')` on the delta is O(chunk);
- the full concatenation now happens only on the chunk that completes a tag.

Behaviour is unchanged: the tag split across chunk boundaries is still handled, and a tag that appears wholly inside a delta still splits the block.

## Performance

This branch, `bun` 1.4.2:

| fixture | before | after |
|---|---|---|
| 470 KB code-heavy stream (`<` in every chunk), appended 200 chars at a time | concatenated the block per chunk — O(block), quadratic over the stream (the 470 KB case was measured at ~430 ms once blocks were long) | **6.51 ms** |
