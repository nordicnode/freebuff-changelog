 *              The Convex cron action returns immediately, and for pool
 *              provisioning neither the runner subscription nor the Convex
 *              fallback batch is started.

 * The invariant every reader enforces: for each job EXACTLY ONE runner does

 * deploy and a freebuff-web deploy are not atomic: in the gap the job runs

/**
 * Where the warm-pool QUEUE (`daytona_pool_job`) lives (COD-742,
 * docs/freebuff-project-pool.md "Reconciliation"):
 *
 * - `convex`   Convex's table, through `pool_management`'s mutations.
 * - `postgres` Postgres `daytona_pool_job`: freebuff-web's reconcile inserts
 *              the deficit, the dispatcher lists it and the provisioner claims
 *              and settles rows there. Convex's `replenishPoolIfEmpty` and
 *              its schedulers step aside.
 *
 * Only honoured while both `reconcile_pool` and `provision_pool` run on
 * graphile: the Convex reconciler and the Convex fallback batch only know
 * Convex's rows. A flip back is this one line; rows left in either store are
 * an abandoned queue (the next reconcile refills from the other), never data.
 */
export type PoolJobStore = 'convex' | 'postgres'

export const POOL_JOB_STORE: PoolJobStore = 'postgres'

export function poolJobsOnPostgres(
  store: PoolJobStore = POOL_JOB_STORE,
  runners: SandboxJobRunners = SANDBOX_JOB_RUNNERS,
): boolean {
  return (
    store === 'postgres' &&
    sandboxJobOwnedBy('reconcile_pool', 'graphile', runners) &&
    sandboxJobOwnedBy('provision_pool', 'graphile', runners)
  )
}

/**
 * Whether `runner` owns `job`. The ONLY question either side asks: the Convex
 * cron asks `sandboxJobOwnedBy(job, 'convex')` and no-ops on false; the
 * graphile task asks `sandboxJobOwnedBy(job, 'graphile')` and no-ops on false.
 * Because the table holds exactly one runner per job, exactly one answers
 * true. An unknown runner value (a bad edit) answers false for both — the job
 * stops rather than runs twice, which for a sweep that deletes VMs is the
 * safe failure.
 */
export function sandboxJobOwnedBy(
  job: SandboxJobName,
  runner: SandboxJobRunner,
  runners: SandboxJobRunners = SANDBOX_JOB_RUNNERS,
): boolean {
  const owner = runners[job]
  if (owner !== 'convex' && owner !== 'graphile') return false
  return owner === runner
}

/**
 * Who FIRES each platform Convex cron whose data stays in Convex for now —
 * the checked-in switch for moving their scheduling off Convex (COD-742,
 * docs/freebuff-jobs.md). In either mode the same code reads and writes the
 * same Convex tables; only the process that starts it changes. Moving the
 * data is each domain's own work and brings its own switch.
 *
 * - `convex`   (default): today. The Convex cron fires; the graphile task logs
 *              and returns.
 * - `graphile` The freebuff-jobs crontab fires the task, which asks
 *              freebuff-web (`POST /api/admin/convex-cron-jobs`) to run the job
 *              over the Convex admin client; the Convex cron returns at once.
 *
 * Exactly one runner per job, as in ./sandbox-jobs-runner.ts: both sides read
 * this one table, so a flip is a single reviewed diff. Never an env var.
 *
 * How a Convex function tells the two apart: the cron passes
 * `trigger: 'cron'` and returns at once unless Convex owns the job;
 * freebuff-web passes `trigger: 'graphile'` and the function refuses unless
 * graphile owns it. A call with no trigger (a self-scheduled next page, an
 * admin's manual run) always runs.
 *

 * `FREEBUFF_WEB_INTERNAL_URL` and `SPEND_ROLLUP_CRON_SECRET`, and freebuff-web

 * Convex and need nothing new. In the gap between the Convex and freebuff-web

 /**
  * Whether `runner` owns `job`. The ONLY question either side asks: the Convex
  * cron asks `sandboxJobOwnedBy(job, 'convex')` and no-ops on false; the
  * graphile task asks `sandboxJobOwnedBy(job, 'graphile')` and no-ops on false.
  * Because the table holds exactly one runner per job, exactly one answers
  * true. An unknown runner value (a bad edit) answers false for both — the job
  * stops rather than runs twice, which for a sweep that deletes VMs is the
  * safe failure.
  */
 export function sandboxJobOwnedBy(
   job: SandboxJobName,
   runner: SandboxJobRunner,
   runners: SandboxJobRunners = SANDBOX_JOB_RUNNERS,
 ): boolean {
   const owner = runners[job]
   if (owner !== 'convex' && owner !== 'graphile') return false
   return owner === runner
 }
